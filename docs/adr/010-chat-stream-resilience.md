# ADR-010：对话流的宿主从 SSE 生成器挪进独立任务（断线续写 + 超时预算）

日期：2026-08-29（P3.2）
状态：已接受

## 背景

P2 的对话流把图执行写在 SSE 生成器里：客户端断开 = 生成器被取消 =
assistant 不落库、token 白烧且不记账（ADR-008 后果段已点名）。还有对称
问题：上游卡死时流永远不结束，连接与图互相陪葬。

## 决策

生产端/消费端解耦：图执行 + 落库 + 记账挪进独立 asyncio.Task（生产端），
SSE 生成器只从 asyncio.Queue 消费（消费端）。

- **断线续写**：断开只取消消费端；生产端跑完、照常落库与记账，用户刷新
  页面即见完整回答——断开不再等于白烧；
- **超时预算由生产端自守**（断开后没有消费端替它计时）：块间 120s、
  全程 300s；超时按失败处理（error 事件、不落 assistant）——半截回答
  进历史会污染后续 condense 语境，宁缺毋残。

## 阈值（怎么定的）

对话模型单调用 timeout 30s（get_chat_model 交互口径：qwen-flash 单轮
秒级，30 已是 P99 包络；研究图的 240s 防错杀口径不适用于「用户正在等」
的路径）× 节点 RetryPolicy 3 次 + 退避 ≈ 单节点最长合法静默 ~92s →
块间取 120（三成余量）；三节点串行全部打满 ≈ 270s + 索引载入 → 全程 300。

## 后果

- 生产端任务由模块级强引用集合 _producers 托住（asyncio 对 task 只留
  弱引用）；app 关停时未完的生产端随事件循环终止，dev 可接受，正经部署
  配 graceful shutdown 等待期；
- 超时中止的那次调用拿不到 usage（连接被掐断，端点不再回传）——记账
  只含已完成调用，缺失计入 missing_calls 的语义不变（ADR-008）；
- SSE 事件协议与两段式持久化不变，P2 前端零改动。
